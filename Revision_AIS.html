Révision AIS – Administration et sécuriser les infrastructures

Objectif global : Maîtriser les standards, les processus et les méthodes qui permettent d'administrer une infrastructure informatique de manière fiable, sécurisée, documentée et professionnelle.

FICHE 1 – Les bonnes pratiques dans l'administration des infrastructures

1. Référentiels de bonnes pratiques

Définition : Référentiel = cadre méthodologique qui décrit comment organiser, sécuriser et gérer un système d'information.

  • ITIL v4 : gestion des services IT (incident, problème, changement...)
  • ISO 27001 : sécurité de l'information
  • ISO 20000 : gestion des services informatiques
  • NIST CSF : cadre de cybersécurité américain
  • ANSSI : recommandations françaises pour la sécurité

Pourquoi c'est important :

  • Standardise les pratiques
  • Réduit les incidents
  • Améliore la qualité de service
  • Structure l'organisation IT

2. Principes des SLA (Service Level Agreement)

Définition : Contrat ou engagement qui définit le niveau de service attendu : disponibilité, performance, délais de résolution.

  • Exemples :
  • Disponibilité 99,9 %
  • Temps de réponse < 200 ms
  • Résolution d'incident critique < 4 h

Utilité :

  • Base de la relation entre IT et métiers
  • Permet de mesurer la qualité de service

3. Gestion des niveaux de service

Définition : Suivi des indicateurs (KPI) pour vérifier que les SLA sont respectés.

  • Mesurer
  • Comparer
  • Corriger
  • Documenter

4. Démarche de diagnostic logique et efficace

Définition : Méthode pour identifier la cause d'un dysfonctionnement.

  1. Identifier le symptôme
  2. Reproduire le problème
  3. Isoler la cause
  4. Tester une solution
  5. Documenter

5. Processus de gestion des incidents et des problèmes

Incident : Interruption ou dégradation d'un service – objectif : restaurer rapidement.

Problème : Cause profonde d'un ou plusieurs incidents – objectif : corriger durablement.

Processus ITIL :

  • Détection
  • Qualification
  • Priorisation
  • Escalade
  • Résolution
  • Clôture

6. Processus de gestion des mises en production

Définition : Déploiement d'une nouvelle version, d'un correctif ou d'un service.

  • Planification
  • Tests
  • Validation
  • Communication
  • Documentation

7. Vérifier l'adéquation de la qualité de service

Objectif : Comparer la qualité réelle du service avec les SLA définis.

  • Supervision
  • Rapports
  • Indicateurs de performance

8. Interpréter et exploiter les informations d'un système de supervision

Définition : Supervision = surveillance en temps réel de l'état des équipements et services.

  • Alertes
  • Logs
  • Graphiques (CPU, RAM, latence...)
  • Seuils

9. Planifier des interventions d'administration et de MCO

Définition : MCO (Maintien en Condition Opérationnelle) = actions pour maintenir un système en fonctionnement optimal.

  • Maintenance préventive
  • Maintenance corrective
  • Fenêtres d'intervention

10. Établir une procédure de traitement d'incidents

  • Détection
  • Qualification
  • Priorisation
  • Escalade
  • Résolution
  • Communication
  • Clôture

11. PRA / PCA

PRA : Plan de Reprise d'Activité – permet de redémarrer après un sinistre.

PCA : Plan de Continuité d'Activité – permet de ne jamais s'arrêter, même en cas de panne.

  • RTO : Recovery Time Objective
  • RPO : Recovery Point Objective

12. Tester les procédures PRA / PCA

  • Vérifier la faisabilité
  • Mesurer les temps réels
  • Identifier les points faibles
  • Adapter les procédures

Résumé fiche 1

ITIL, ISO, ANSSI – SLA et qualité de service – diagnostic structuré – gestion des incidents / problèmes / changements – supervision – MCO – PRA / PCA.

FICHE 2 – Utiliser un logiciel de gestion centralisée GLPI

Objectif : Comprendre, installer et exploiter GLPI pour gérer les équipements, les tickets, les utilisateurs et les opérations d'administration dans une infrastructure IT.

Définitions essentielles

  • GLPI : logiciel open-source de gestion de parc, tickets, demandes, utilisateurs, contrats, licences, support.
  • Parc informatique : ensemble des équipements matériels et logiciels (PC, serveurs, imprimantes, licences...).
  • Ticket : enregistrement d'un incident ou d'une demande utilisateur.
  • Inventaire automatique : remontée automatique des infos des machines (FusionInventory, OCS Inventory).

1. Installer GLPI

  • Installation serveur web (Apache ou Nginx)
  • Installation de PHP + extensions
  • Installation base de données (MySQL/MariaDB)
  • Déploiement des fichiers GLPI
  • Configuration initiale (admin, base, plugins)

À retenir : GLPI fonctionne en mode web, accessible via navigateur, souvent avec FusionInventory pour l’inventaire.

2. Utiliser GLPI

  • Gestion des tickets : création, suivi, priorisation, affectation
  • Gestion des utilisateurs : rôles, permissions, groupes
  • Gestion du parc : ordinateurs, serveurs, logiciels, réseaux
  • Gestion des contrats : maintenance, garanties, fournisseurs
  • Gestion des licences : conformité, expiration
  • Base de connaissances : documentation interne

Rôle : ensemble de permissions attribuées à un utilisateur (technicien, administrateur...).

3. Exploiter des données GLPI

  • Statistiques des tickets (temps de résolution, nombre d’incidents...)
  • État du parc (machines obsolètes, licences expirées...)
  • Historique des interventions
  • Rapports pour la direction / responsable IT

Utilité : améliorer la qualité de service, identifier les problèmes récurrents, optimiser les ressources.

4. GLPI pour l'administration du réseau

  • Documenter les équipements réseau (switch, routeur, firewall)
  • Associer les ports réseau aux machines
  • Suivre les incidents réseau
  • Planifier les interventions
  • Centraliser les infos pour le MCO

Résumé fiche 2

GLPI est un outil central pour gérer les incidents, suivre le parc, documenter l’infrastructure, analyser les performances du support, structurer l’administration réseau.

FICHE 3 – Configurer le routage

Objectif : Comprendre, configurer et sécuriser les équipements réseau (routeurs, commutateurs), mettre en place le routage, les VLAN, la redondance et la supervision.

1. Équipements d’interconnexion

Définition : matériel permettant de relier plusieurs réseaux ou segments réseau.

  • Commutateur (switch) : relie des machines dans un LAN
  • Routeur : relie plusieurs réseaux (LAN <> WAN)
  • Passerelle (gateway) : point de sortie d’un réseau
  • Pare-feu : filtre le trafic
  • Point d’accès Wi-Fi : interconnexion sans fil

2. Configuration routeur / commutateur

Routeur :

  • Interfaces (IP, masque)
  • Routes statiques
  • Routage dynamique (OSPF, RIP, BGP)
  • Sécurisation (ACL, filtrage, SSH)

Commutateur :

  • Configuration des ports
  • Activation des VLAN
  • Spanning-tree
  • Sécurisation (port-security, storm-control)

3. VLAN et routage inter-VLAN

VLAN : segmentation logique d’un réseau sur un même switch.

  • Sécurité
  • Organisation
  • Réduction du broadcast

Routage inter-VLAN : via routeur (router-on-a-stick) ou switch de couche 3.

4. Commutation de couche 3

Switch capable de faire du routage (L3) en plus de la commutation (L2) – utile pour le routage inter-VLAN avec de bonnes performances.

5. Redondance d’un commutateur

  • Spanning Tree Protocol (STP)
  • RSTP / MSTP
  • Empilement (stacking)

6. Mise en œuvre d’un protocole de routage

Statique : routes définies manuellement.

Dynamique :

  • RIP : simple, ancien
  • OSPF : performant, entreprise
  • BGP : entre opérateurs (Internet)

7. Redondance d’un routeur

  • HSRP (Cisco)
  • VRRP (standard)
  • GLBP

Objectif : assurer une passerelle de secours.

8. Monitorer commutateurs et routeurs

Outils : SNMP, Syslog, ICMP, solutions de supervision (Centreon, Zabbix, PRTG).

  • CPU / RAM
  • Température
  • Erreurs ports
  • Débit
  • Disponibilité
  • Latence

Résumé fiche 3

Rôle des équipements, configuration routeurs/switches, VLAN et routage inter-VLAN, redondance, protocoles de routage, supervision réseau.

FICHE 4 – Administrer et sécuriser le réseau

Objectif : Administrer, sécuriser et surveiller un réseau d’entreprise : Wi-Fi, pare-feux, proxies, bastions, IDS/IPS, VPN, interconnexions, BYOD, QoS, documentation, incidents.

1. Réseaux sans fil (Wi-Fi)

  • Modes de sécurité : WPA2-Enterprise, WPA3
  • Gestion des SSID (invités, internes)
  • Puissance d’émission
  • Isolation des clients
  • Authentification RADIUS

Risques : intrusions, Evil Twin, mauvaise segmentation.

2. Pare-feux

  • Firewall réseau, WAF, firewall local
  • ACL, NAT/PAT, inspection de paquets
  • Filtrage URL / ports, détection d’anomalies

3. Proxies

  • Filtrage web
  • Contrôle d’accès
  • Cache
  • Journalisation

4. Bastions

Serveur sécurisé pour accès administrateurs : centralisation, enregistrement des sessions, moindre privilège.

5. IDS

Détection d’intrusion par signatures ou comportement, génération d’alertes.

6. IPS

Détecte et bloque les attaques en temps réel (Snort, Suricata, Cisco Firepower).

7. VPN

  • SSL VPN
  • IPsec VPN
  • Site-to-site
  • Client-to-site

8–9. Connexions intersites / opérateurs

  • MPLS
  • VPN IPsec
  • Fibre dédiée
  • SD-WAN
  • Fibre pro, liaisons point-à-point, 4G/5G entreprise

10. BYOD

Risques : perte de données, absence de contrôle, malware.

Solutions : MDM, conteneurisation, politiques de sécurité.

11. QoS

Priorisation des flux (VoIP, visioconférence, applis critiques) via marquage DSCP, files d’attente, limitation de bande passante.

12. Analyse des dysfonctionnements réseau

  • Ping, traceroute
  • Analyse des logs
  • Ports (errors, drops)
  • Vérification des VLAN
  • Contrôle des ACL

13–14. Documentation et CMDB

Schémas réseau, procédures, inventaire, historique des incidents.

CMDB : base de données des équipements, versions, relations – facilite diagnostics et changements.

Résumé fiche 4

Wi-Fi, pare-feux, proxies, bastions, IDS/IPS, VPN, interconnexions, BYOD, QoS, documentation, CMDB, analyse des incidents.

  • Permissions (chmod)

  • Gestion des erreurs (if, exit, codes retour)

3. Tâches automatisables

  • Sauvegardes
  • Nettoyage de logs
  • Création d’utilisateurs
  • Déploiement de logiciels
  • Surveillance de services
  • Redémarrage automatique

4. Traitement automatisé

Scripts de sauvegarde quotidienne, vérification d’espace disque, redémarrage de service.

Outils : cron (Linux), Task Scheduler (Windows).

5. Recherche de scripts et sécurité

  • Sources : GitHub, docs officielles, communautés, scripts internes

Exemples : SELECT * FROM utilisateurs;, INSERT INTO logs ..., UPDATE machines SET statut='OK';

FICHE 7 – Les bases des serveurs virtualisés

Objectif : Virtualisation, solutions, fonctions avancées, architectures convergentes, data centers, clusters, licences, bases du cloud.

1. Solutions de virtualisation

Virtualisation : plusieurs VMs sur un serveur physique via hyperviseur.

  • VMware ESXi
  • Microsoft Hyper-V
  • Proxmox VE
  • KVM/QEMU
  • VirtualBox

2. Fonctions avancées

  • vMotion / Live Migration
  • High Availability (HA)
  • Fault Tolerance (FT)
  • Snapshots
  • Clonage

3. Convergé / hyper-convergé

Infrastructure convergée : serveurs + stockage + réseau.

Hyper-convergence (HCI) : calcul, stockage, réseau dans les mêmes nœuds (vSAN, Nutanix, Azure Stack HCI).

4. Impact de la virtualisation

  • Avantages : coûts, ressources, isolation, déploiement rapide, HA
  • Inconvénients : dépendance hyperviseur, compétences, surallocation

5–6. Data centers et clusters

Data center : site physique avec serveurs, stockage, réseau, climatisation, sécurité, alimentation.

Cluster : groupe de serveurs hébergeant des VMs – nœuds, stockage partagé, réseau dédié, hyperviseur.

7. Licences en virtualisation

  • Licences par hôte, par VM, par CPU/core, cloud à l’usage
  • Risques : non-conformité, surcoûts, audits

8. Introduction à Azure

Azure : VMs, stockage, VNet, services managés (SQL, AD, Kubernetes), sécurité (IAM, MFA), scalabilité, paiement à l’usage.

9. Introduction à AWS

AWS : EC2, S3, RDS, VPC, IAM – large catalogue, fiabilité, flexibilité.
